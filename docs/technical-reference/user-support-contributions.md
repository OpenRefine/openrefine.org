If you have used OpenRefine to solve a problem, you can help someone else through the same steps. A reply on the forum can also help the next person who searches for the same question.

## Answer a question on the forum

Browse [Support and Helpdesk](https://forum.openrefine.org/c/support/12) and pick a question about something you have tried. People ask for help getting OpenRefine running, cleaning data and using extensions. Read the thread to see what they want to do and what they have already tried.

Suppose someone writes, “My dates come out wrong.” You might ask, “Could you share one made-up date as it appears in your column, the result you want, and the steps you tried?” An example like `03/04/2025` can reveal that two people are reading the same date differently.

Try your suggestion on the example. Describe one next step and what the person should see. A link to the relevant section of the [user manual](../index.md) can help them try it themselves. The [forum guidelines](https://forum.openrefine.org/guidelines) ask everyone to be courteous. Explain unfamiliar terms and say when you are unsure.

## Help investigate unexpected results

If you see the same problem, post the shortest set of steps that produced it. Include the OpenRefine version you used, what you expected and what happened. If your result differs, describe it too. For installation or extension problems, the [helpdesk introduction](https://forum.openrefine.org/t/about-the-support-and-helpdesk-category/61) lists details worth asking for. Use invented or shareable data and check screenshots for private information before posting.

## Help with testing and issue triage

Issue triage means helping people understand and sort reports. When a discussion points to a bug or feature request for OpenRefine itself, search the [issue tracker](https://github.com/OpenRefine/OpenRefine/issues) first. Add any new evidence to an existing issue. For a new bug, the [bug report template](https://github.com/OpenRefine/OpenRefine/blob/master/.github/ISSUE_TEMPLATE/bug_report.md) shows which details to include. For a feature request, explain what the person is trying to do and how the change would help. Link the issue and the forum thread so people can follow up. If an extension or external service might be responsible, ask in the thread where to report it.

You can also try a proposed fix when a contributor asks for testers. Use a copy of your data, identify the version or build you tried and report whether the original steps now give the expected result.
